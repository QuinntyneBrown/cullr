# L1 - High-Level Requirements

Derived from the screens, dialogs and notifications in `docs/mocks/` and the
product description in `AGENTS.md`. Cullr has exactly one user, the owner.

## L1-001: Owner authentication
The system must let only its owner sign in, stay signed in, recover a forgotten
password and sign out. Every screen except the authentication screens and the
public error screens must require an authenticated owner.

## L1-002: Capture ideas
The system must let the owner log an idea they already have, quickly, from the
Today and Ideas screens. The system does not generate ideas.

## L1-003: Review today's ideas
The system must show the owner the ideas logged today, which one is today's
best, and how many were logged.

## L1-004: Browse, search and sort ideas
The system must let the owner browse every active idea and narrow it by status,
category and text, sort it, and act on several ideas at once.

## L1-005: View, critique and edit an idea
The system must let the owner open one idea, read its summary, critique notes
and status history, and edit its title, summary, category and critique notes.

## L1-006: Idea lifecycle
The system must track each idea through the statuses Logged, Critiquing,
Curating, Building and Built, and record every status change in the idea's
history.

## L1-007: Curate best-of ideas
The system must let the owner promote an idea to best of today, this week, this
month or the year so far, and must show the current best-of ideas for each
period, from the day up to the year.

## L1-008: Archive, restore and delete ideas
The system must let the owner archive an idea with an optional reason, restore
an archived idea, and permanently delete an archived idea after explicit
confirmation. Archived ideas must be read-only.

## L1-009: Notifications
The system must tell the owner about events that matter (curation, daily
volume heads-up, carry-over, export outcome) and let the owner mark them read.

## L1-010: Settings and export
The system must let the owner configure the daily capture reminder, the daily
heads-up threshold and automatic dark theme, and export all ideas as a
spreadsheet.

## L1-011: Account profile
The system must let the owner view and edit their profile (name, email, areas
of expertise) and change their password.

## L1-012: Resilience and system states
The system must show a clear, recoverable screen or message for loading,
empty, error, no-results, offline, forbidden, not-found and server-error
conditions, and must never lose the owner's input on a failed save.

## L1-013: Responsive layout
The system must be usable at every viewport width from phone to large desktop,
with generous whitespace and no loss of function at any width.

## L1-014: Accessibility
The system must meet WCAG 2.2 AA in light and dark themes, including full
keyboard operation and assistive-technology support.

## L1-015: Security
The system must protect the owner's ideas and credentials against the OWASP Top
10, including authentication, session management, input validation and data
protection.

## L1-016: Performance
The system must feel immediate at the owner's expected volume of around 100
new ideas a day and thousands of stored ideas.
