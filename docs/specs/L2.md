# L2 - Detailed Requirements

Each requirement traces to one L1 in `L1.md` and to the mocks in `docs/mocks/`.
Viewport classes: XS < 576px, SM >= 576px, MD >= 768px, LG >= 992px,
XL >= 1200px.

## L2-001: Sign in
**Traces to:** L1-001

The Sign in screen (`/sign-in`) must authenticate the owner with email and
password.

**Acceptance Criteria:**
1. Given the owner's valid email and password, when the owner submits the form, then the owner is signed in and taken to Today.
2. Given the form is submitting, when the request is in flight, then the submit button is disabled and shows a busy state and the fields cannot be edited.
3. Given an email or password that does not match, when the owner submits, then a single generic message "Email or password is incorrect" is shown and the response does not reveal which of the two was wrong.
4. Given an empty email or password, when the owner submits, then the field shows an inline error and the request is not sent.
5. Given the sign-in service is unreachable, when the owner submits, then the "Sign-in service is unreachable" error and a "Try again" action are shown and the typed email is kept.
6. Given a signed-in owner, when the owner opens `/sign-in`, then the owner is redirected to Today.

---

## L2-002: Sign-in lockout
**Traces to:** L1-001

**Acceptance Criteria:**
1. Given 5 consecutive failed sign-ins for the owner's account within 15 minutes, when a sixth attempt is made, then it is rejected with the same generic message until the 15-minute window ends.
2. Given a lockout, when the owner uses a correct password during the window, then sign-in is still rejected.

---

## L2-003: Forgot password
**Traces to:** L1-001

The Forgot password screen (`/forgot-password`) must send a reset link.

**Acceptance Criteria:**
1. Given any well-formed email, when the owner submits, then the success state "check your email" is shown regardless of whether the email is the owner's.
2. Given the email is the owner's, when the owner submits, then exactly one reset email is sent containing a single-use link that expires in 60 minutes.
3. Given a malformed or empty email, when the owner submits, then an inline error is shown and no request is sent.
4. Given the service fails, when the owner submits, then the error state is shown and the typed email is kept.

---

## L2-004: Reset password
**Traces to:** L1-001

The Reset password screen (`/reset-password`) must set a new password from a reset link.

**Acceptance Criteria:**
1. Given a valid unexpired link and a new password that meets the password policy (L2-046) and matches its confirmation, when the owner submits, then the password is changed, the link is invalidated and the success state is shown.
2. Given the confirmation differs from the new password, when the owner submits, then "Passwords don't match" is shown inline and no request is sent.
3. Given an expired or already-used link, when the owner opens or submits it, then the error state explains the link is no longer valid and offers a path to request a new one.
4. Given a successful reset, when it completes, then every existing session is revoked.

---

## L2-005: Sign out and session expiry
**Traces to:** L1-001

**Acceptance Criteria:**
1. Given a signed-in owner, when the owner signs out, then the session is destroyed server-side and the owner lands on Sign in.
2. Given a session idle for 30 days or older than 90 days, when the owner makes any request, then the request is rejected and the owner is sent to Sign in with a return to the original page after sign-in.
3. Given a signed-out visitor, when they request any protected screen or API, then they are redirected to Sign in or receive 401, and no idea data is returned.

---

## L2-006: Capture an idea
**Traces to:** L1-002

The Capture idea dialog must log a new idea. It opens from the "Capture idea" action on Today and Ideas.

**Acceptance Criteria:**
1. Given the dialog opens, then it shows Title, Summary, Category (exactly one of Toronto & GTA, Photography, Faith & ministry, Product, Engineering) and Score (optional, a whole number from 1 to 10), focus is on Title, and "Capture idea" is the primary action.
2. Given a title of 1 to 120 characters, a summary of up to 1,000 characters, a category and an optional score, when the owner captures, then the idea is saved with status Logged and the logged time set to now, the dialog closes, a success notification names the idea, and the idea appears on Today and at the top of Ideas.
3. Given an empty or whitespace-only title, when the owner captures, then "Enter a title for this idea" is shown inline, the summary of errors says "Fix 1 error before capturing this idea", and nothing is saved.
4. Given the save is in flight, then the primary action is busy and disabled, Cancel and Escape are the only ways out, and a second submit is not possible.
5. Given the save fails, then the dialog stays open with a failure message and all entered values are kept, and retrying does not create a duplicate idea.
6. Given text over the length limits, when the owner types, then input is rejected at the limit with a visible counter.
7. Given the owner has unsaved input, when the owner presses Escape or Cancel, then the dialog closes and nothing is saved.
8. Given a score that is not a whole number from 1 to 10, when the owner captures, then "Enter a whole number from 1 to 10" is shown inline and nothing is saved.
9. Given no score is entered, then the idea is saved without a score and shown as "Not scored".

---

## L2-007: Duplicate-safe capture
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given the same capture request is delivered twice (double-click or network retry), when both reach the server, then exactly one idea is created.

## L2-008: Today summary
**Traces to:** L1-003

The Today screen (`/`) must summarise the day.

**Acceptance Criteria:**
1. Given ideas logged today, then the subtitle reads "N ideas logged today" followed by today's date, and, when at least one idea is best of today, names today's best idea, which is the best-of-today idea with the highest score, ties broken by the latest curated.
2. Given ideas logged today, then they are listed with title, category, status, score out of 10 (or "Not scored"), summary excerpt, logged time, and Curate and Archive actions, and each best-of-today idea is marked "Best of today".
3. Given 0 ideas logged today, then the empty state "No ideas logged yet today" with a Capture idea action is shown.
4. Given a category filter chip is chosen, then only today's ideas in that category are shown, and when none match the no-results state offers to clear the filter.
5. Given a very long title or summary, then text wraps or truncates with an accessible full value and the layout does not overflow at any viewport width.
6. Given a count over 999, then it is shown with thousands separators (for example 1,284).
7. Given the data is loading, then a skeleton placeholder is shown, and given the load fails, then an error with a retry action is shown.
8. Given a day boundary, then "today" is determined in the owner's time zone (default America/Toronto).

---

## L2-009: List active ideas
**Traces to:** L1-004

The Ideas screen (`/ideas`) must list every active (non-archived) idea.

**Acceptance Criteria:**
1. Given active ideas, then each row shows title (linked to the idea), category, status, logged time, score, and Edit and Archive actions, and the subtitle shows the count logged this quarter, active and archived.
2. Given more than 50 ideas, then the list is paginated or incrementally loaded so that at most 50 rows are rendered per page.
3. Given no active ideas, then the empty state with a Capture idea action is shown.
4. Given the load fails, then an error with a retry action is shown, and while loading a skeleton is shown.
5. Given XS viewport, then rows are presented as stacked cards with no horizontal scroll of the page.

---

## L2-010: Filter, sort and search ideas
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given the status tabs All, Logged, Critiquing, Curating and Building, when the owner selects one, then only ideas with that status are listed, the tab shows aria-selected, and the counts stay accurate.
2. Given the category chips, when the owner toggles chips, then only ideas in the selected categories are listed, and each chip exposes its pressed state.
3. Given the Sort control, when the owner chooses Newest first, Score (highest first, unscored last) or Status (in lifecycle order), then the list reorders accordingly and the choice is kept while the owner stays on the screen.
4. Given the search box, when the owner types a query, then ideas whose title, summary or critique notes contain the query (case-insensitive) are listed, results update after at most 300 ms of typing pause, and the query is URL-addressable.
5. Given filters or a query that match nothing, then the no-results state names the filter or query and offers "Clear filters".
6. Given tab, chips, sort and query together, then they combine with AND semantics.

## L2-011: Select multiple ideas
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given the Ideas list, when the owner selects one or more rows, then a bar shows "N selected" with "Curate selected", "Archive selected" and "Clear selection".
2. Given "Select all", then every row currently listed (not only the visible page) is selected and the bar says so.
3. Given a bulk action is confirmed, when some items fail, then the successes are applied, the failures are reported by title, and selection is kept only for the failures.
4. Given "Clear selection", then the bar disappears and no row is selected.
5. Given the owner selects more than 5 ideas, then "Curate selected" is disabled with the explanation "Select up to 5 ideas to curate", and given 1 to 5 active ideas are selected, then "Curate selected" opens the Curate idea dialog and applies the chosen period to every selected idea.

4. Given a very long title or summary, then the layout does not overflow at any viewport width.
5. Given the page, then Curate, Archive and Edit idea actions are available for an active idea.

## L2-013: Edit an idea
**Traces to:** L1-005

The Edit idea dialog must change an existing active idea.

**Acceptance Criteria:**
1. Given an active idea, when the dialog opens, then Title, Summary, Category, Score and Critique notes are prefilled with the saved values.
2. Given valid changes, when the owner saves, then the idea is updated everywhere it appears (Today, Ideas, Curated, Idea detail), the dialog closes and a success notification is shown.
3. Given an empty title, or a score that is not a whole number from 1 to 10, when the owner saves, then an inline error is shown and nothing is saved.
4. Given the save is in flight, then the primary action is busy and disabled.
5. Given the save fails, then the dialog stays open with a failure message and the edits are kept.
6. Given the idea was changed elsewhere since the dialog opened, when the owner saves, then the owner is told the idea changed and can review before overwriting.
7. Given an archived idea, then no edit action is offered and the server rejects edits.
8. Given an idea with status Logged, when the owner saves non-empty critique notes, then its status becomes Critiquing (L2-014).

## L2-014: Idea status lifecycle
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given a newly captured idea, then its status is Logged.
2. Given an idea, then its status is exactly one of Logged, Critiquing, Curating, Building or Built.
3. Given any status change, then an entry with the new status and its time is added to the idea's status history and is never removed or edited.
4. Given an idea is curated, then a history entry "Curated as best of <period>" is added.
5. Given an idea is archived or restored, then history records it.
6. Given an idea with status Logged, when the owner first saves non-empty critique notes, then the status becomes Critiquing automatically.
7. Given an idea with status Logged or Critiquing, when it is curated, then the status becomes Curating automatically.
8. Given an idea with status Curating, Building or Built, or a Building or Built idea that is curated, then automatic rules never change its status to an earlier one.

## L2-052: Set status manually
**Traces to:** L1-006

The Idea detail screen must let the owner mark an active idea as Building or Built.

**Acceptance Criteria:**
1. Given an active idea, when the owner opens the status control on Idea detail, then it offers exactly Building and Built.
2. Given the owner chooses a status, when the owner confirms, then the idea has that status, a history entry is added, and a success notification is shown.
3. Given the owner chooses the status the idea already has, then nothing changes and no history entry is added.
4. Given the save fails, then the previous status is still shown and a failure message with a retry action is shown.
5. Given an archived idea, then the control is not offered and the server rejects the change.

## L2-015: Curate an idea
**Traces to:** L1-007

The Curate idea dialog must promote an idea to a best-of list. It opens from Today, Ideas (single and bulk) and Idea detail.

**Acceptance Criteria:**
1. Given the dialog opens, then it offers exactly Best of today, Best of this week, Best of this month and Best of the year so far, with the first preselected and each showing its carry-over rule.
2. Given a period is chosen, when the owner confirms, then the idea becomes that period's best-of, the dialog closes and a success notification is shown.
3. Given a period already holds 5 best-of ideas, when the owner curates another idea into it, then the idea curated earliest into that period stops being best of it and the success notification names that idea.
4. Given the save is in flight, then the primary action is busy and disabled.
5. Given the save fails, then the dialog stays open with a failure message and the choice is kept.
6. Given an archived idea, then curating is not offered and the server rejects it.
7. Given an idea already best of the chosen period, when the owner confirms, then nothing changes and the owner is told it is already best of that period.
8. Given the owner curates several ideas at once (L2-011), when the owner confirms, then every selected idea is curated into the chosen period, and the 5-idea limit is applied to the period as a whole.

**Traces to:** L1-007

The Curated screen (`/curated`) must show the current best-of ideas.

**Acceptance Criteria:**

Given best-of ideas exist, then they are listed in the order today, this week, this month, year so far, with the ideas of one period ordered by score (highest first, unscored last), each labelled with its period, title, category, status and summary, and the subtitle reads "N ideas curated as of <date>" where N counts distinct ideas.

3. Given a category chip filter matches nothing, then the no-results state offers to clear the filter.
4. Given loading or a failed load, then a skeleton or an error with retry is shown.

## L2-017: Best-of period end and carry-over
**Traces to:** L1-007

A period's best-of ideas are kept until the period ends, then lapse. An idea may be best of several periods at once, and lapsing from one period does not remove it from another.

**Acceptance Criteria:**
1. Given ideas are best of today, when the day ends in the owner's time zone, then they stop being best of today.
2. Given ideas are best of this week, when the week ends on Sunday in the owner's time zone, then they stop being best of this week.
3. Given ideas are best of this month, when the month ends, then they stop being best of this month.
4. Given an idea is best of the year so far, then it remains until it is replaced under L2-015 criterion 3 or the year ends.
5. Given an idea lapses from a period and is still best of the next higher period (today to week, week to month, month to year so far), then it is carried over: it remains best of that higher period and a carry-over notification is created (L2-024).
6. Given an idea lapses from a period and is not best of the next higher period, then it simply stops being best of the period and no notification is created.

## L2-036: Responsive layout
**Traces to:** L1-013

**Acceptance Criteria:**
1. Given XS viewport, then primary navigation is collapsed behind a menu button with aria-expanded, content is a single column, and every action remains available.
2. Given SM and MD viewports, then content uses the available width with generous whitespace and tables degrade to cards when columns cannot fit without horizontal page scroll.
3. Given LG and XL viewports, then the sidebar is permanently visible and content width is capped at a readable maximum.
4. Given any viewport from 320px to 1920px wide, then there is no horizontal page scrolling and no content is clipped.
5. Given dialogs at XS viewport, then they fit the viewport height with their own scrolling and keep primary actions reachable.
6. Given browser zoom to 200 percent, then all functionality remains usable.

## L2-037: Keyboard and focus
**Traces to:** L1-014

**Acceptance Criteria:**
1. Given any screen, then every interactive control is reachable and operable by keyboard in a logical order, with a visible focus indicator that has at least 3:1 contrast.
2. Given any screen, then a "Skip to content" link is the first focusable element.
3. Given a dialog opens, then focus moves into it, focus is trapped while open, Escape closes it unless a save is in flight, and focus returns to the element that opened it.
4. Given status tabs, then they follow the tabs pattern with arrow-key navigation.

## L2-038: Assistive technology
**Traces to:** L1-014

**Acceptance Criteria:**
1. Given any screen, then it has one h1, landmarks (navigation, main, search), and each table has an accessible caption and column scope.
2. Given a validation error, then it is associated with its field by aria-describedby, the field is marked aria-invalid, and the error summary receives focus.
3. Given a toast, loading state or result-count change, then it is announced through a live region.
4. Given any icon without text, then it has an accessible name, and decorative icons are hidden from assistive technology.
5. Given an action is busy, then aria-busy or an equivalent is exposed.

---

## L2-039: Colour, contrast and motion
**Traces to:** L1-014

**Acceptance Criteria:**
1. Given light or dark theme, then text has at least 4.5:1 contrast (3:1 for large text and UI components) against its background.
2. Given any status, then it is conveyed by text as well as colour.
3. Given the owner prefers reduced motion, then non-essential animation is disabled.
4. Given touch input, then interactive targets are at least 24 by 24 CSS pixels.

---

## L2-040: Transport and headers
**Traces to:** L1-015

**Acceptance Criteria:**
1. Given any request over HTTP, then it is redirected to HTTPS and responses carry Strict-Transport-Security.
2. Given any response, then it carries a Content-Security-Policy that forbids inline script and third-party script, `X-Content-Type-Options: nosniff`, a frame-ancestors restriction and a strict referrer policy.

---

## L2-041: Session security
**Traces to:** L1-015

**Acceptance Criteria:**
1. Given a session, then its cookie is Secure, HttpOnly and SameSite=Lax or stricter, and its identifier is regenerated on sign-in.
2. Given a state-changing request, then it is rejected unless it carries a valid anti-CSRF token or equivalent origin check.

---

## L2-042: Input validation and output encoding
**Traces to:** L1-015

**Acceptance Criteria:**
1. Given any request, then the server validates every field for type, length and allowed values regardless of client validation and rejects invalid input with 400 and field-level errors.

## Decisions and follow-ups

Decided with the owner on 2026-10-14:

1. **Score:** the owner sets an optional whole-number score of 1 to 10 in the Capture idea and Edit idea dialogs (L2-006, L2-013).
2. **Auto-archive:** there is none. The notification "Couldn't auto-archive Sprint Bingo" does not exist as a requirement (L2-024).
3. **Status:** Critiquing and Curating are set automatically; Building and Built are set by the owner on Idea detail (L2-014, L2-052).
4. **Category:** exactly one category per idea.
5. **Carry-over:** a best-of idea is kept until its period ends, then lapses; it is carried over, with a notification, when it is still best of the next higher period (L2-017, L2-024).
6. **Bulk curate:** a period holds up to 5 best-of ideas, and up to 5 selected ideas may be curated at once (L2-011, L2-015).
7. **Limits:** title 120, summary 1,000, reason 500, 50 rows per page, 12-character passwords and 5 failed sign-ins in 15 minutes are accepted as proposed.

Mocks that must change to match these decisions before implementation:

- Capture idea and Edit idea dialogs: add the Score field and its invalid state.
- Idea detail: add the Building/Built status control.
- Notifications: remove "Couldn't auto-archive Sprint Bingo" from the mock data.
- Ideas, Today and Curated edge mocks: show one category per idea.
- Curated and Today: show several best-of ideas per period.
- Ideas: "Curate selected" disabled state when more than 5 ideas are selected.
