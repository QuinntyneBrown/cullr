Text field

A single-line text input with a visible label, optional help and an error.

Overview

Use for short free text: titles, names, search. For several lines use textarea; for a fixed set of values use select. Always wrap it in a form field.

Anatomy

  1. LabelAlways visible, above the input.
  2. InputHeight from --control-height-md, 1px strong border.
  3. Help text (optional)Format or limits, before the user types.
  4. Error (when invalid)Icon + text, linked by aria-describedby.

Variants

Standard, with help, and search.

Sizes

Small 32px, medium 40px, large 48px.
HTML
<input class="input input--sm" aria-label="Small" value="Small"><input class="input" aria-label="Medium" value="Medium"><input class="input input--lg" aria-label="Large" value="Large">

Input

Read-only inputs use the readonly attribute and a subtle fill.

Responsive behaviour

  • Inputs are full width of their column; forms cap at 32rem.
  • Font is at least 16px so iOS does not zoom on focus.

Accessibility

Role and pattern

Native <input> inside a <label>. Search uses role="search" on the form.

Keyboard

Keyboard
KeyAction
Tab / Shift+TabMoves focus to and from the control in DOM order.
EscIn search, clears the text.

Focus

Border becomes --color-accent and a 2px ring appears.

Labelling

Visible <label> always; placeholder is an example, never the label. Help and error link via aria-describedby; invalid sets aria-invalid="true". Add autocomplete where it applies (1.3.5).

Contrast

Input border
Placeholder
Error text
Focus ring on surface

Motion

No motion beyond the shared hover and focus transitions, which use --duration-fast and are removed under prefers-reduced-motion.

Touch

Targets are at least 24px and 44px where the control stands alone; neighbouring targets are 8px apart.

Content

  • Nouns for labels: Title, not Enter the title.
  • Errors: what is wrong + the fix.
